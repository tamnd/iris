# iris-btr

A reader for the BtrBlocks column format, checked against the reference implementation.

BtrBlocks is a columnar compression format that picks a scheme per column by sampling the data, and then often stacks a second scheme on top of the first one's output. This crate reads a compressed column part and hands back the values, in safe Rust, with no C++ toolchain anywhere in the build.

The gate is byte identical output. `conformance/btrblocks` in the repository holds a corpus generated by linking against the reference, asking it to compress a column and asking it to decode the result, so every case records the compressed part, the values the reference got out of it, and which rows it said were present. This crate reads the same parts and has to produce the same answers to the byte. Any deviation is a bug here until the reference is proven wrong, and the fixtures are committed, so running that suite needs no network and no C++.

What is implemented so far is the part and chunk framing, every one of the four nullmap encodings including the two that are a Roaring bitmap, the two schemes that carry no compression for all three column types, bit packing for integer columns, and dictionaries for integer and double columns. That is thirteen of the twenty two cases in the corpus. Bit packing came before the rest of the schemes because most of them cascade through it, a dictionary storing its codes bit packed and a run length encoding storing its values the same way. A scheme that is not implemented yet returns an error saying so rather than a wrong answer, and it is a different error from a scheme the reference does not define, because those two say different things about whose problem it is.

This crate depends on nothing but `thiserror`, and does not depend on the rest of iris. Reading a format and returning values is worth being able to build and test on a host.
